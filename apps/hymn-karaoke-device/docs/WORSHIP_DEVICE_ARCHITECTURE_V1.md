## Intent
Turn the EXISTING karaoke device app into a full worship-service presentation app usable at a church.
**Two role-separated UIs**:
- `/display?room=...`: big TV/projector only. Never show admin controls, login widgets, settings, browser-like menus, clipboard, QR with controller rights, or debugging info while live.
- `/control?room=...`: conductor's phone/tablet/presenter laptop with accessible search, 0-9 number keypad, queue, preview/Go Live, prior/next verse, pause/blank/nature standby.
- Optional `/stage`: confidence monitor for preacher/song leader, different content from attendee TV. Not the default.

Use QR **pairing invitation** distinct from a public read-only QR. Room codes must expire/rotate and be exchanged for scoped authorization (presenter role) via auth rules; URLs alone must not grant arbitrary external control. One active conductor, multiple read-only displays; prevent stale command replay and collisions with sequence monotonic counter/ack.

## Worship service feature coverage
1. Hymn: 1–645 keypad mapping for verified 21st-century hymnal numbering. Each hymn has `hymnId`, print edition/number, alternate numbers and translated original titles, score MusicXML, lyrics-per-verse, language, local backing audio/media, checked rights. Missing/unapproved resources show an honest unavailable state, never fabricated text. Advance verse using button/touch; X41 precise syllable note clock for approved timed songs only. 1- or 2-line language choice, with text wrapping.
2. Bible: 66 books, book/chapter/start verse-end verse selector plus shorthand search (예: 시23:1-6). Show clearly `시편 23편 1–2절`, always render exact verse reference + edition (개역개정/개역한글1910/etc.). Measure pixel wrapping at actual monitor size. Paginate by verse/sentence, not approximate character count only, preserve punctuation and numbering. Never cut off bottom; manual next/previous verse/touch, optional operator-controlled auto-advance disabled by default. Original-language/interlinear later, separate permissions.
3. Formal worship text: Lord's Prayer (주기도문), Apostles' Creed (사도신경) and Responsive Reading (교독문). Content editions belong to chosen church/denominational tradition and should include leader/congregation alternating display modes. Do not auto-generate doctrinal changes; verify version and redistribution license first.
4. Queue/service-order editor: worship opening/background -> call to worship/creed -> responsive reading -> hymn -> prayer -> Bible reading -> sermon passage -> offertory hymn -> benediction/Lord's Prayer -> background. Save named order as data; quick previous/next/specific jump, operator PREVIEW vs LIVE two-step to avoid accidental live text.
5. Nature idle screen: pre-approved nature footage loops quietly when there is no live worship item, after a user-selected idle interval, or on a controlled transition. If network drops, fall back to locally cached LICENSED clips or deterministic SVG sunrise/ocean/snow generated by existing code pack. **A crashed JS process cannot switch its own screen** — local watchdog / TV wrapper recovery required. Ensure natural 16:9, no abrupt black frame, brightness QC; no added music without operator approval.
6. Live video/audio: local Chrome player for licensed media, no automatic public distribution of existing unfinished 4-verse MP4. Reuse existing FFM for exporting offline MP4 (not necessary for every live slide). Remotion for reusable decoration, not for rendering each Bible verse on server.

## Transport path in stages (do not claim finished)
A. Same laptop, separate Chrome tabs: `BroadcastChannel` works only between compatible same-origin browser contexts. Use local-only pilot to prove transitions; not usable by a phone on another device just because the URL matches.
B. Different phone and TV: reuse an AUTHORIZED existing Firestore project / bridge if actual credentials/rules readback shows it is healthy; otherwise request approval for a separate live transport. Cloud Firestore `onSnapshot` provides low-frequency synchronized slide state and offline cache; secure per-session presenter writes/read-only display reads via Firebase Auth and Security Rules. A TV must not permit unauthorized writes. Config must not be silently added to GitHub secrets. Maintain 1 active show session and monotonic `seq` with ack to prevent stale events. Reconnection restores **last verified current slide**, not blindly skipping forward.
C. In-building no-WAN: the existing notebook can serve a local LAN HTTP/WebSocket bridge; phone uses same Wi-Fi with pairing, cached legal media content in browser. This requires verified local process/startup and network permissions; Vercel static deployment by itself cannot run the LAN server.
Display fallback after >15s no active command: NO accidental verse change; only nature standby if stage not live / consented timeout. Network disconnect while live should hold last live slide (not silently replace scripture).
